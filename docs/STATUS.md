仿真器：

- 网页连 `ws://<同一地址>/device`，断了 2 秒后重连，右侧显示连接状态。
- `snapshot.mjs` 在同一个进程里跑电脑端服务和假 agent，时钟从 2026-11-14 14:32（东八区）开始，结果可重复。新加 `--hold x,y`（长按）、`--offline`、`--verbose`。
- `simulator/tools/render-ui.sh` 一次出全部 13 张图到 `design/renders/ui-*.png`，包括批准后的列表、长按批准页、出错页、没连上电脑。
- 你反映“点击后略有抖动”，查下来是仿真器自己的毛病：以前用整个设备外壳左右晃 1 像素来表示震动，晃动量是小数像素，屏幕会被插值变虚，看起来就像界面在抖。现在外壳不动，震动在右侧面板用指示灯显示。
- 同时查出：界面每次重画都重建整屏，时钟走一分钟也会让整屏重新刷一遍、重新叠一遍灰度。现在仿真器的屏幕模型像 SSD1677 一样记住上次显示的内容，只驱动变了的像素，灰度叠加也只补重画过的像素；右侧面板显示每次刷新的区域。实测一次时钟重画：黑白只动 226 个像素，灰度只补 1563 个（以前整屏 14013 个）。

接真机时要做的（固件还没开始）：

- `ct_hal_net_send()`、`ct_hal_battery_percent()` 两个函数；收到的消息要在界面线程里交给 `ct_ui_on_message()`；cJSON 用 ESP-IDF 自带的同一个版本；会话内存走 `malloc`，要开 PSRAM 分配。
- 屏幕驱动要比较新旧两帧，只刷有变化的区域，灰度叠加只补重画过的像素，规则和 `simulator/web/sim.js` 开头的说明一样。不这样做，每分钟的时钟重画都会整屏重新驱动，费电，灰度像素被重复叠加还会越来越深。

## 第 7 项：接 Claude Code 钩子（已完成）

真的 Claude Code 会话现在会出现在设备上，能在设备上批准、拒绝、回答它的提问。

怎么用：

```sh
cd bridge
node src/main.ts hooks --merge ~/.claude/settings.json   # 加钩子，旧文件留 .codetalky.bak
node src/main.ts --fake                                  # 起服务（--fake 可省）
node src/main.ts hooks --remove ~/.claude/settings.json  # 不用了就撤掉
```

钩子是 Claude Code 自带的 HTTP 钩子，发到 `http://127.0.0.1:8137/hooks/claude`。只有 SessionStart 例外：Claude Code 规定它只能是命令型钩子，所以用转发脚本 `bridge/hooks/hook.mjs`（和 Codex 共用）。服务没开时 Claude Code 照常工作，钩子连不上不会拦它。我没有改你的 `~/.claude/settings.json`，要不要加由你决定。

怎么工作的（`bridge/src/claude/`）：

- 一个 Claude Code 会话对应设备上一行，名字是项目文件夹名；模型名和 git 分支从会话记录里读，读不到就显示“—”。
- 你每发一条指令开始新的一轮：计数、改动文件、改动片段清零；活动记录保留。
- 每一步工具调用记一条：读了多少行、搜到几处、改了几行（用 Claude Code 自己的补丁，改动片段带真实行号）、命令完成或失败。待办列表来自它的 TodoWrite。
- 完成汇报用它最后一段回复，Markdown 的要点、加粗开头会变成汇报里的圆点和粗体。
- 批准请求：设备连着时，钩子等设备回话，期限默认 570 秒（`--hold` 可改）。交互式 Claude Code（2.1.323 实测）在钩子等待的同时，终端里也照常弹确认框，两边谁先答算谁的：
  - 设备先答，终端的确认框自己消失，接着干活；
  - 终端先答，Claude Code 挂断钩子请求，设备马上离开批准页，显示“已在电脑上处理”（万一没挂断，看到这个工具的结果也会离开）；
  - 期限到了、设备断了、或者根本没设备连着，钩子不给结论，终端的确认框还在，照常在电脑上答。
- 改文件的请求在设备上显示要改的行，会去文件里找出第几行；命令显示整条，理由用命令自带的说明。删除、推送、强推、`reset --hard` 这类命令要长按批准。
- 同时来的几个请求排队，一个一个显示。
- 它用 AskUserQuestion 提问时，在设备上点选项回答；一次问几道题就依次显示。
- 一次性运行（`claude -p`）一结束会话就关了，汇报会留着，你点“知道了”才移走；正常退出的会话直接移走；12 小时没动静的会话也会清掉。
- 普通终端里开的会话不能从设备发新指令（设备上显示“只能查看”），要等“托管终端”。

实测过（用最便宜的 haiku 模型，在临时目录里跑，三次一共约 0.01 美元）：

- `claude -p` 让它跑一条命令：设备上出现等批准，点批准后命令真的执行了。
- `claude -p` 让它改一个文件：设备上看到要改的行，批准后改动片段和 Claude Code 的补丁一致，完成汇报的要点正确。
- 交互式 Claude Code（用 pywinpty 开的伪终端）让它用 AskUserQuestion 提问：设备上点了选项，终端里显示收到了答案，它的回复里说的就是这个选项。`claude -p` 模式里没有 AskUserQuestion，只能这样测。
- 11-13 托管终端整套（`codetalky claude --model haiku --permission-mode default`，测试脚本同时扮演设备和坐在终端前的人，终端画面用 xterm 无头终端截下来）：
  - 启动 3 秒设备上就出现会话，能发指令；中文指令打进输入框并提交了。
  - 第 1 个批准在设备上点：155 毫秒后 Claude Code 继续。
  - 它正忙时设备发第 2 条指令：Claude Code 排进队里，做完手上这步就接着做。
  - 第 2 个批准在终端里按回车：0.5 秒后设备离开批准页。
  - 第 3 个批准谁都不答：20 秒（测试时把期限调短了）后设备放手，终端确认框还在，回车后照常完成。
  - 发现并改掉的问题：SessionStart 不收 HTTP 钩子，会话要等第一条指令才出现，设备没法发第一条（改成命令型）；终端里答了，设备还停在批准页（改成跟着挂断走）；命令前面的 `cd "项目目录" &&` 挤掉了命令本身（是本项目目录就不显示）；读一行的文件显示“2 行”；完成后“正在做”没清；新一轮还显示上一轮汇报的话。
  - 你的 Claude Code 默认是 auto 模式，大部分操作它自己放行，不会来问设备；测试时用 `--permission-mode default` 强制每步都问。

安全：

- 钩子入口只接受本机发来、并且不带 Origin 头的请求，网页伪造不了。
- 设备从别的机器连进来一律拒绝，等配对口令做好再放开；早期接真机调试可以加 `--insecure-lan`（会打印警告）。

还没做的：

- 计划确认（ExitPlanMode）还是在终端里确认，设备上不显示计划。
- 多选题在设备上只能选一个；不能自己写答案。

## 多台电脑（你 11-13 提的要求，已完成）

局域网里可以有几台电脑在跑 agent，每台上也可以有好几个 agent。

- 每台电脑各开一个电脑端服务，用 `--name 台式机` 起个名字（默认是电脑名）。设备同时连所有电脑，最多 4 台。
- 所有会话合在一张列表里，仍按“等你的排前面”排。连着不止一台电脑时，列表每行写“台式机 · opus-5.5”，详情、批准页、提问页也写出电脑名；状态栏显示“2 台电脑”。
- 批准、回答、发指令都发回会话所在的那台电脑；快速回复每台电脑各用各的。
- 一台电脑断线：状态栏变成“1/2 台在线”，它的会话标“笔记本（离线）”，保留 5 分钟，重连就接着用，超过才移走。
- 每台电脑有固定编号（`~/.codetalky/bridge-id`），以后配对用它认电脑，换 IP 不受影响。
- 在一台电脑上演示两台：开两个服务，`--port 8138 --name 笔记本 --fake-only blog-engine,landing,api-server`，网页地址加 `?bridges=127.0.0.1:8137,127.0.0.1:8138`。截图工具用 `--hosts 2`，`--unlink 1` 模拟一台掉线。图在 `design/renders/ui-14` 到 `ui-16`。

10. （已做，11-13 真 Codex 实测通过，见下面）接 Codex。本机的 Codex CLI 11-13 从 0.136 升到了 0.169（当时的最新版），用 ChatGPT 账号登录，`codex doctor` 检查全部正常；钩子功能是稳定版，默认开着。和 Claude Code 的区别：
    - 钩子只能是命令，没有 HTTP 型，所以用一个转发脚本 `bridge/hooks/hook.mjs` 把事件交给电脑端服务（`/hooks/codex`），再把答复打印回去；电脑端没开时打印 `{}`，Codex 照常问你。脚本用 `node:http` 而不是 `fetch`，因为 `fetch` 等响应头最多 300 秒，批准要等更久。
    - 新钩子要先信任：合并配置后启动 codex，输入 `/hooks` 信任一次。有个每次跳过信任的启动参数（`--dangerously-bypass-hook-trust`），会连别的钩子一起放行，不用。
    - `~/.codex/` 是 Codex 命令行和桌面版共用的，文档说桌面版的设置里也能信任钩子。所以钩子加进 `~/.codex/hooks.json`（并信任）以后，桌面版里的会话应该也会出现在设备上、能在设备上批准，但不能从设备发指令（那要托管终端）。还没实测。
    - `codetalky codex` 启动时直接用 node 跑 npm 装的 `codex.js`，不经过 cmd.exe，参数里有 `&`、引号也不会被改。
    - 改文件走 `apply_patch`，一次可以改好几个文件，补丁是它自己的格式，已写了解析（`bridge/src/codex/patch.ts`），行号到文件里找；命令失败看退出码。
    - 模型名直接在事件里；分支直接读项目的 `.git/HEAD`（Claude 也用上了）。
    - 文档没说钩子能不能回答 Codex 的提问，所以 Codex 先只做批准，不做提问。
    - 批准请求的等待、排队、超时交回终端、托管终端（`codetalky codex`）和 Claude 共用同一套代码。
    - 11-13 真 Codex 实测（gpt-6-luna、低推理强度、只读沙盒，脚本扮演设备和坐在终端前的人）发现的情况和改法：
      - Codex 要到第一条指令提交时才开始会话（SessionStart 那时才来），设备看不到刚启动的 `codetalky codex`，没法发第一条指令。改成：启动器一连上电脑端服务，设备上就有这个会话（编号 `run-` 开头）；Codex 的会话来了接管同一条，设备页面不跳。Claude 也一样，`/clear` 换了会话也还是同一条。
      - 钩子在等设备时，Codex 不画自己的确认框（终端只显示 “Running hook”），直到钩子返回。所以托管的 Codex 不再让钩子等：钩子立刻返回，确认框马上出现在终端里；设备上批准或拒绝，就是启动器在终端里按 `y` 或 Esc。按之前先看屏幕上确实有确认框（启动器用 `@xterm/headless` 留一份屏幕），没有就不按，设备上提示一句。直接运行的 `codex`（和桌面版）还是让钩子等设备，那期间电脑上答不了。
      - 在 Codex 里按 Esc 拒绝会结束这一轮，而且不发 Stop。设备拒绝后显示“已拒绝，它停下来了，等你的下一条指令”。
      - `apply_patch` 不发 PostToolUse，改动记不下来；它的 PreToolUse 说的是 Bash，命令是 `apply_patch <<'PATCH' …`。改成：Bash 里的 apply_patch 当补丁显示；改了什么从 Codex 的会话记录文件（钩子里的 `transcript_path`）读，那里有 `item_completed` 的 FileChange（每个文件的 unified diff）和 AgentMessage（它边做边说的话，设备上的 say 也有了）。头一次读到的是历史，不算。
      - 什么时候要批准由模型决定（0.169 的审批策略只剩 `on-request` 和 `never`）。只读沙盒里便宜模型会直接报“没权限”而不申请，测试时在指令里让它直接申请提权。
    - 顺带修的一个两边都有的问题：终端里弹着确认框时，设备发来的指令如果直接打进去，它的回车（Codex 里还有字母 y）会替你答了确认框。现在启动器打字前先看屏幕，确认框还在就等它没了再打。
    - 实测结果：启动 0.4 秒设备上就有会话，设备发第一条指令；设备批准后 0.17 秒 Codex 继续；终端里答了，0.9 秒后设备离开批准页；设备期限到了终端的确认框还在；确认框弹着时设备发的指令等到确认框答完才打进去，Codex 也照做了；设备拒绝后 Codex 停下、设备显示停下了；退出后会话消失。

## 配对（已完成）

局域网里的设备要先配对才能连电脑，本机连接（仿真器）不用。设备第一次连某台电脑时显示 6 位配对码，你在那台电脑上运行 `codetalky pair <配对码>` 确认；电脑发给设备一个令牌，设备按电脑编号存起来，以后自动认证。

- 只有能操作那台电脑的人才能配对；配对前设备发的动作一律不算。
- 电脑只存令牌的哈希（`~/.codetalky/devices.json`）；`codetalky devices` 列出，`codetalky unpair` 撤销，撤销后设备下次连会被拒并重新要求配对。
- 配对码 5 分钟有效，设备快到时自动换新码；点“以后再说”不再弹出，列表里留着提示。
- 加 `--require-pairing` 可以在仿真器里试配对界面；截图工具用 `--pair`、`--approve`、`--relink`。图在 `design/renders/ui-17`、`ui-18`。
- 硬件接口加了持久存储和随机数（真机用 NVS 和 esp_random）。
- 已知局限：令牌走不加密的 WebSocket，同网段能抓包的人可以重放。以后改成挑战应答，令牌就不必在网上传。
- `--insecure-lan` 还在，意思变成“局域网设备跳过配对”，只供调试。
